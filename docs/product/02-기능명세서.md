| 객체 | 필드 | 규칙 |
|---|---|---|
| 지원 대상 | 직무, 기업, 산업 | 직무는 시작 필수, 기업·산업은 이후 보완 가능 |
| 기업 자료 | 직접 붙여넣은 참고 텍스트, 분석 결과, 사용 승인 | URL 자동 수집 없음 |

| 연결 | 역량, 관련 경험, 연결 이유, 보완 질문, 근거 수준 | 백분율 점수 금지 |

| 작업 공간 | 실제·예시 모드, 스키마 버전 | 두 모드의 저장 영역 분리 |

## 공통 기능

### FR-001 작업 공간 저장

- 입력과 결과는 현재 브라우저에 자동 저장합니다.
- 새로고침 후 같은 모드의 마지막 상태를 복원합니다.
- 저장 실패 시 사용자가 알아볼 수 있는 안내를 표시합니다.
- 실제 모드와 예시 모드는 서로의 데이터를 덮어쓰지 않습니다.

### FR-002 진행 상태

- 7개 단계의 현재 위치와 완료 여부를 표시합니다.
- 완료된 이전 단계로 이동할 수 있습니다.
- 다음 단계로 이동해도 현재 입력은 유지됩니다.
- 미완료 단계 진입 시 필요한 선행 작업을 안내합니다.

### FR-003 AI 상태

| 상태 | 화면 동작 |
|---|---|
| 대기 | 실행 버튼과 현재 입력 표시 |
| 로딩 | 진행 문구와 스켈레톤 표시, 중복 요청 방지 |
| 성공 | 결과와 수정 기능 표시 |
| 빈 화면 | 아직 결과가 없다는 문구와 시작 행동 표시 |
| 일반 오류 | 재시도, 가능한 경우 입력 수정 제공 |
| 요청 제한 | 잠시 후 재시도하라는 문구 표시 |
| 연결 불가 | 연결 불가 안내와 명시적 예시 진입 버튼 표시 |

AI 실패는 현재 입력과 기존 결과를 삭제하지 않습니다. 합성 결과를 자동으로 출력하지 않습니다.

### FR-004 개인정보 안내

- 작업 공간 상단에서 브라우저 저장과 AI 전송 시점을 알립니다.
- 주민등록번호, 계좌번호, 비밀번호, API key 입력 금지를 표시합니다.
- 결과 화면에서 지원 전 사실과 수치를 확인하도록 안내합니다.

## 단계별 기능

### FR-100 시작

입력: 지원 직무, 지원 기업
행동: `분석 시작`, `예시로 둘러보기`

수용 기준:

- 지원 직무가 비어 있으면 `분석 시작`을 실행할 수 없습니다.
- 실제 입력 후 시작하면 산업 분석 화면으로 이동합니다.
- 예시를 선택하면 예시 표식이 나타나고 실제 작업은 보존됩니다.

### FR-110 산업 분석

입력: 관심 산업, 지원 직무
출력: 산업 구조, 주요 변화, 직무 영향, 추가 확인 사항

수용 기준:

- 사용자가 입력한 산업과 직무가 분석 요청에 반영됩니다.
- 결과는 화면에서 직접 수정할 수 있습니다.
- 최신 정보로 단정하지 않고 공식 자료 확인 안내를 유지합니다.

### FR-120 기업 분석

입력: 기업명, 산업, 지원 직무, 직접 붙여넣은 기업 참고자료
출력: 기업 개요, 사업, 제품, 해결 문제, 직무 연결, 추가 조사 질문

수용 기준:

- 참고자료가 없어도 분석을 요청할 수 있습니다.
- 임의 URL을 서버에서 가져오지 않습니다.
- 분석 결과를 문서 작성에 쓰려면 사용자가 확인 항목을 선택해야 합니다.
- 기업 관련 입력이나 분석이 바뀌면 기존 사용 승인을 해제합니다.

### FR-130 JD 분석

입력: 회사명, 산업, 지원 직무명, JD 전체 텍스트
출력: 직무 정의, 주요 업무, 필수 역량, 우대 역량, 키워드, 증명 항목, 경험 질문

수용 기준:

- JD가 비어 있으면 유효한 분석 결과를 생성하지 않습니다.
- 숫자형 적합도와 합격 가능성을 표시하지 않습니다.
- 분석 결과는 사용자가 수정할 수 있습니다.
- JD 변경 시 연결·인사이트·문서 결과를 다시 검토하도록 상태를 갱신합니다.

### FR-140 경험 관리

입력 필드는 공통 데이터의 경험 객체를 따릅니다.

수용 기준:

- 경험은 최소 1개, 최대 10개를 관리할 수 있습니다.
- 경험 추가, 삭제, 선택, 위·아래 이동을 지원합니다.
- 팀이 한 일과 본인이 한 일을 분리해 적을 수 있습니다.
- 결과 수치가 없더라도 경험 저장은 가능합니다.
- 삭제 전 확인을 받고, 삭제된 경험을 선택 목록과 문서 입력에서 제외합니다.

### FR-150 경험 보완

출력: 각 경험의 부족한 정보를 묻는 추가 질문

수용 기준:

- 경험을 바로 재작성하기보다 보완 질문을 먼저 제안합니다.
- 질문은 해당 경험 ID와 연결됩니다.
- 기존 입력은 질문 생성 뒤에도 유지됩니다.
- 사용자는 질문을 참고해 경험 필드를 직접 수정합니다.

### FR-160 역량 연결

입력: JD 분석 결과, 선택 가능한 경험
출력: 역량별 관련 경험, 연결 근거, 추가 질문, 정성 라벨

수용 기준:

- JD 분석과 경험이 없으면 선행 작업 안내를 표시합니다.
- 관련 경험이 부족하면 임의 경험을 만들지 않고 추가 정보 필요로 표시합니다.
- 라벨은 강한 근거·보통 근거·추가 정보 필요 수준의 정성 표현만 사용합니다.
- 백분율이나 합격 가능성 점수는 사용하지 않습니다.

### FR-170 인사이트

입력: 경험과 직무 연결 결과
출력: 반복되는 해결 방식, 판단 패턴, 강점 후보, 직무 연결, 차별화 이야기

수용 기준:

- 새 인사이트는 `확인 전` 상태로 생성됩니다.
- 사용자는 각 인사이트를 `이 인사이트 사용`, `수정`, `사용하지 않음`으로 처리합니다.
- 수정한 인사이트는 다시 확인 전 상태가 됩니다.
- 승인된 인사이트만 문서 생성 입력으로 사용합니다.

### FR-180 문서 공통

수용 기준:

- 사용자는 문서에 사용할 경험을 선택합니다.
- 기업 분석이 존재하면 문서 사용 전 기업 분석 확인이 필요합니다.
- 승인 인사이트 1개 이상과 선택 경험 1개 이상이 있어야 생성할 수 있습니다.
- 결과의 모든 문장은 사용자가 직접 수정할 수 있습니다.
- 사용자 입력에 없는 매출·성장률·사용자 수·수상·직급·기술·기간을 새 사실로 추가하지 않습니다.

### FR-181 이력서

출력 섹션: 핵심 역량, 경력, 프로젝트, 교육, 기술

- 입력 근거가 없는 섹션은 비워두고 그 이유를 표시합니다.
- 각 문장을 개별 편집할 수 있습니다.
- 전체 결과를 복사할 수 있습니다.

### FR-182 자기소개서

입력: 실제 질문, 최대 글자 수 100~3000자

- 첫 요청은 질문 의도, 주장, 경험 근거, 전개 구조가 담긴 설계안을 생성합니다.
- 설계안 생성만으로 자기소개서 본문을 만들지 않습니다.
- 사용자가 `초안 작성`을 선택한 뒤 본문을 생성합니다.
- 본문 길이와 최대 글자 수를 함께 표시합니다.
- 초안 수정, 복사, 다시 작성을 지원합니다.

### FR-183 포트폴리오

입력: 선택된 프로젝트 경험 1개

출력: 한 문장 소개, 문제, 리서치, 인사이트, 판단, 실행, 결과, 학습, 직무 연결

- 현재 선택한 프로젝트 이름과 지원 직무를 표시합니다.
- 프로젝트 선택 변경 시 기존 결과를 다시 검토하거나 재생성해야 합니다.
- 각 블록을 직접 수정하고 전체 내용을 복사할 수 있습니다.

### FR-190 데이터 관리

- 현재 공간을 JSON 파일로 내보냅니다.
- 불러오기 전 현재 공간 교체 확인을 받습니다.
- 파일 크기와 스키마를 확인한 뒤에만 데이터를 바꿉니다.
- 잘못된 파일은 오류를 표시하고 기존 데이터를 유지합니다.
- 전체 삭제 전 확인을 받고 실제·예시·이전 버전 데이터를 제거합니다.
