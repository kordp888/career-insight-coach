# iOS 앱 TestFlight 등록 절차

iOS 앱의 가제는 **커리어 AI 웨이브**입니다. 웹 서비스 이름(커리어코치)과 별개로 홈 화면과 App Store Connect 에서 쓰는 이름입니다. 이 앱은 배포된 웹앱(`/coach`)을 그대로 띄우는 얇은 껍데기입니다. 화면, 저장 방식, AI 연결 상태는 웹과 같습니다. 웹에 반영된 변경은 앱을 다시 올리지 않아도 앱에 보입니다. 앱을 다시 올려야 하는 경우는 아이콘, 이름, 권한, 시작 주소처럼 iOS 프로젝트 자체가 바뀔 때뿐입니다.

| 항목 | 값 |
|---|---|
| 번들 ID | `com.kordp888.careercoach` |
| 홈 화면 이름 | 커리어 AI 웨이브 (가제) |
| 제품 이름(내부) | `App` (ASCII. 한글 제품 이름은 IPA 경로가 깨져 업로드가 거절됩니다) |
| 버전 | 1.0 |
| 시작 주소 | `https://career-insight-coach.vercel.app/coach` |
| 최소 iOS | 15.0 |
| 암호화 신고 | `ITSAppUsesNonExemptEncryption = NO` (표준 HTTPS만 사용) |

## 한 번만 하는 준비

사람만 할 수 있는 단계입니다. Apple 계정에 로그인해야 하기 때문입니다.

1. **번들 ID 등록.** developer.apple.com 의 Certificates, Identifiers & Profiles 에서 Identifiers 에 App ID 를 추가합니다. 설명은 CareerCoach, 번들 ID 는 위 표의 값(Explicit)입니다. 추가 기능은 켜지 않아도 됩니다.
2. **배포 프로파일 생성.** 같은 화면의 Profiles 에서 Distribution 의 App Store Connect 유형을 고르고, 1번의 App ID 와 **기존** Apple Distribution 인증서를 선택합니다. 이름은 알아보기 쉽게 정합니다(예: CAREERCOACH). 내려받아 더블클릭하면 Xcode 에 설치됩니다.
   - 배포 인증서는 팀당 두 개가 한도입니다. 새로 만들지 마십시오. 새로 만들려면 기존 것을 폐기해야 하고, 그러면 그 인증서를 쓰는 다른 앱의 프로파일이 깨집니다.
   - 같은 이름의 배포 인증서가 둘이면 프로파일에 들어간 쪽의 SHA-1 을 확인해 둡니다. 아래 스크립트에 이름 대신 SHA-1 을 넣어야 합니다.
3. **App Store Connect 앱 생성.** 나의 앱에서 새로운 앱을 만들고 플랫폼 iOS, 기본 언어 한국어, 번들 ID 는 1번 값을 고릅니다. 앱 이름은 가제 "커리어 AI 웨이브"를 씁니다. App Store 전체에서 겹치면 안 되므로 이미 있으면 뒤에 한 낱말을 붙이는 식으로 정합니다. 홈 화면 이름은 이것과 별개입니다.

## 빌드 올리기

인증서와 프로파일이 설치된 맥에서 실행합니다.

```bash
IOS_TEAM_ID=<팀 ID> IOS_PROFILE=<2번에서 정한 프로파일 이름> IOS_SIGN_IDENTITY=<배포 인증서 SHA-1> ./scripts/ios-archive.sh
```

스크립트는 웹 자산 동기화, 수동 서명 아카이브, IPA 내보내기, 서명과 경로 검증까지 하고 멈춥니다. 빌드 번호는 기본으로 실행 시각이라 올릴 때마다 자동으로 커집니다. 결과 IPA 는 `~/Desktop/CareerCoach-ios/` 아래에 생깁니다.

업로드는 **Transporter** 앱으로 직접 합니다. Apple 계정으로 로그인하고 IPA 를 끌어다 놓은 뒤 전송을 누릅니다.

## TestFlight 배포

1. 업로드 뒤 App Store Connect 의 TestFlight 탭에 빌드가 나타나기까지 보통 15~60분 걸립니다.
2. **내부 테스트**는 심사가 없습니다. 내부 그룹을 만들고 App Store Connect 사용자로 등록된 사람을 테스터로 추가하면 바로 설치할 수 있습니다(최대 100명).
3. **외부 테스트**는 베타 앱 심사를 거칩니다. 베타 앱 설명, 피드백 이메일, 연락처가 필요합니다. 공개 링크로 모집할 수 있습니다(최대 10,000명).

외부 테스트 전에 확인할 위험이 두 가지 있습니다.

- 웹 화면만 띄우는 앱은 최소 기능(가이드라인 4.2) 사유로 거절될 수 있습니다. 내부 테스트로 먼저 쓰고, 외부로 넓히기 전에 앱에서만 되는 기능을 검토합니다.
- AI 분석이 꺼져 있으면 심사자는 예시 화면만 볼 수 있습니다. 외부 심사는 엔진 공개 연결이 끝난 뒤에 올리는 것이 안전합니다.

## 다시 올릴 때

웹 변경만 있으면 다시 올리지 않습니다. iOS 프로젝트가 바뀌었으면 위 스크립트를 다시 실행합니다. 버전(1.0)을 올릴 때는 Xcode 에서 `MARKETING_VERSION` 을 바꿉니다.

## 문제가 생기면

| 증상 | 원인과 조치 |
|---|---|
| "Communication with Apple failed" | 자동 서명이 막힌 환경입니다. 스크립트처럼 수동 서명을 씁니다 |
| "profile doesn't include signing certificate" | 같은 이름의 인증서 중 다른 쪽이 잡혔습니다. `IOS_SIGN_IDENTITY` 에 SHA-1 을 넣습니다 |
| 업로드 거절 90034 또는 409 | 제품 이름이나 경로에 한글이 들어갔습니다. 검증 단계의 비ASCII 경로 목록이 비어 있어야 합니다 |
| 앱이 "인터넷 연결이 필요합니다"만 보임 | 시작 주소에 닿지 못했습니다. 웹 배포 상태를 확인합니다 |
